# BENCH: версии форка на стендах p7/copy (WSL loopback, 2026-11-06/07)

Сравнение версий Go-форка на стендах `bench/p7-compare.sh` и `bench/copy-compare.sh`
проекта ssh3-c. Прошлые числа взяты из документов ssh3-c: `BENCH-COPY-2026-11-03.md`
и `BENCH-V0.3.0-2026-10-15.md` (версии форка — по датам прогонов, точные коммиты
не пинались). Референс всех строк — OpenSSH (SSH2) на тех же прогонах 2026-11-07:
copy v4 108.6/162.8 MB/s, cold 217.1 мс, warm 12.9 мс, manyfiles 1333/1239 files/s.
Сводка трёх реализаций (SSH2/SSH3C/SSH3GO) живёт в локальной сводке межреализационного стенда.

## Сводка версий

Чтение: cold/warm exec и manyfiles — стабильны от версии к версии (manyfiles pull
восстановился 2730→3607); copy 64 MiB просел 0.1.40-27→0.1.41 (21.7→18.6, 29.8→24.0)
— на 3 раундах близко к шуму, при подтверждении — кандидат на разбор в плане форка.
Функциональных регрессий нет (mux 300/300, manyfiles 7/7 после фикса харнесса).

## Замечания по методике

- 0.1.40-27 снят с промежуточного `bf921c3` (клон `~/git/ssh3` отставал от GitHub
  main по remote `win`); 0.1.41 — GitHub main `b3dc117` (релиз v0.1.41), тот же
  протокол. Урок: при бенчах версий сверять HEAD клона с GitHub (`git fetch origin`),
  а не с промежуточным зеркалом.
- Многиефайлы: числа до 0.1.40-27 сняты sftp-двигателем `-f -r`, дальше — движком
  `-transfer -r`; сравнение двигателей, не чистая деградация.

## Смена CLI (главное изменение между прогонами)

- было: `-f` / `-f -r` — режим файлового трансфера;
- стало: `-f` = «go to background after startup» (ssh2 -f); трансфер —
  `-transfer [-r]`, канон scp — `-sftp`; цель — `user@host:remote_path` с
  `-p PORT -U /ssh3-term`.
- Пин-политика ужесточена: в неинтерактивном режиме хост должен быть в пин-сторе
  либо `-o StrictHostKeyChecking=accept-new`.
- Следствие: харнессы под старый CLI **молча но-оп** — клиент отдавал RC=0 и
  0 файлов. Диагноз и фикс: go-ноги manyfiles/xfer в `bench/p7-compare.sh`
  переведены на `-transfer -r`, stderr go-клиента пишется в `$LOGS`.

## Замечания

- v6 parse-гэп transfer-операнда остаётся (скобочный v6-литерал).
- Регрессия тёплого exec была стороной стенда ssh3-c: волна 1e включила
  password-шаги по умолчанию, Basic-ветка вердикта затенила open-режим демона,
  и filler-токен интероп-мастера стал 401-ить (mux 0/300). Финальный фикс —
  настоящий JWT-мастер: interop-клиент получил `--cm-path` (сокет мастера на
  отдельном флаге, `-U` вернулся к имени пользователя), пара `-K` + `-M`
  разрешена; mux-стенд диалится мастером с `-K` JWT против обычного `-K`
  демона, open-режим больше не нужен. ssh3-c 0.5.10: 300/300, median 8.0 мс.
  У форка mux 300/300 во всех прогонах.
- В составе `bf921c3` — волна 1 zero-copy (`feat/zero-copy-channel`: sync.Pool +
  AppendHeader, 0 allocs на sendMessage) и фикс jump-диалов; на loopback-стенде
  их влияние в пределах шума.
