## R5. Взаимодействие с nginx + ротация сертификатов

- Проверить проксирование QUIC через nginx.
- Технический нюанс: nginx умеет (а) UDP stream proxy — L4 без терминации TLS, (б) HTTP/3-терминацию для своего веб-трафика, но не умеет быть HTTP/3-клиентом к бэкенду. Схема «клиент→nginx сертификат A, nginx→ssh3 сертификат B» потребует терминации на nginx — для сырого ssh3-over-h3 это, скорее всего, не взлетит; реалистичный вариант — L4 UDP-прокси с одним серверным сертификатом. Проверить на практике оба сценария.
- Смена сертификата: ротация на сервере (reload/restart), поведение установленных сессий и resume клиентов.
- **Статус: выполнено 2026-11-11** — методика и результаты в `docs/R5-NGINX-2026-11-11.md` (loopback-цифры, не транспортные). Вердикты: (А) L4 UDP-прокси работает — exec-латентность паритет, throughput ×0.66–0.69 от прямого пути, L4 прозрачен для сертификата и renewal; (Б) HTTP/3-терминация не реализуема — у nginx нет HTTP/3-upstream, а stream-UDP слушатель не терминирует TLS (`ssl_certificate` на UDP парсится, но игнорируется — подтверждено тестом с мёртвым upstream), «двухсертификатная» схема не собирается; ротация — рестарт (live reload нет) с drain-окном сервера (`SSH3_SHUTDOWN_DRAIN`, дефолт 5 с — активные сессии функциональны до конца дрейна), CA-верифицированный renewal перепинывает клиентов автоматически («certificate rotated, chain valid») на обоих путях; Go-клиент cross-run 0-RTT не имеет (тикеты in-process) — сценарий «старый тикет против нового серта» в Go-CLI не существует.

## R7. Настоящее докачивание доверия (AIA + root program) для клиента

- Статус: T1 выполнено 2026-11-11; T2 выполнено 2026-11-11; T3 не начат. Якорь — `docs/CERT-VERIFICATION-CANON.md` (путь «системный CA-стор» + §2.6 AIA); каноническое ограничение: докачанное доверие само якорем не становится.
- Проблема: Go-клиент на Windows строит цепочку по **статичному** содержимому системных сторов; автообновление корней SChannel (`CertGetCertificateChain`) не наследуется — на серверных SKU с усечённым стором (нет ISRG X1/X2) LE-цепочки не верифицируются, клиент требует `-insecure` (кейс: публичный LE-хост на DDNS, 2026-11-08). Зеркальный трек для C-порта: `project/ssh3-c/docs/PLAN.md` §10 (ssh3-c на Windows системные сторы не читает вовсе).
- Фазы (от простого к полному):
  - **T1 CA-bundle bootstrap** — зашитый PEM + файл рядом (Go: `go:embed` + fallback на системный стор). Снимает проблему немедленно, часы работы. **Выполнено 2026-11-11** (`cmd/cabundle.go`): пул клиента = системный стор ∪ зашитые ISRG Root X1/X2 (`go:embed`, PEM byte-exact с letsencrypt.org, SHA-256 отпечатки DER сверены с опубликованными) ∪ опц. `~/.ssh3/ca-bundle.pem` (env `SSH3_CA_BUNDLE`); отсутствие файла — ок, битый — warning и продолжаем с embed+system, ошибка `SystemCertPool` — fallback на зашитые корни; пул — строгое надмножество старого. Тесты `cmd/cabundle_test.go` (9 юнитов, TDD red→green, корни генерируются в тесте — сети нет).
  - **T2 AIA-chasing** — недостающие intermediates добираются по `caIssuers`-URL предъявленных сертификатов, рекурсивно до якоря; недоступность сети — работа на stale-кэше. **Выполнено 2026-11-11** (`cmd/aia.go`, канон §2.6): хук в crypto-error ветке `setupQUICConnection` — capture-диал достаёт предъявленные сертификаты, чейз идёт по `caIssuers`-URL вверх (DER и PEM ответы, глубина ≤8, таймаут fetch ≤5 с, бюджет ≤20 с, кап тела 256 KiB); гейт — `leaf.Verify(Roots: якорный пул (стор ∪ embed ∪ бандл ∪ пины), Intermediates: предъявленные ∪ докачанные)`; retry-хендшейк верифицирует сам (`InsecureSkipVerify`+`VerifyConnection`, `cmd/ssh3.go`) — fetched intermediates ходят только intermediates'ами и **никогда не попадают в якорный пул** (пул-гейт отвергнут: добавление в `RootCAs` делает fetched анкором для чужих цепочек). Кэш `~/.ssh3/aia-cache/` (ключ — SHA-256 URL, PEM, 0600; путь сведён к `~/.ssh3/` ради консистентности с T1 — строка канона поправлена); cache-first + network-forced второй проход на провал гейта (stale/poisoned запись не клинит клиента); тёплый кэш = ноль сетевых запросов на следующих диалах; офлайн — stale-кэш. Пин-вердикты (Matches/Changed/Unknown, SSHFP, rotation re-pin) едут на retry-соединении через общий `finishConnection` — механика пинов не тронута; self-signed leaf и уже-верифицируемая цепочка не чейзятся. Тесты `cmd/aia_test.go` (16 юнитов, TDD red→green, httptest-сервер со счётчиком — внешней сети нет).
  - **T3 root program** — `authrootstl.cab` с `ctldl.windowsupdate.com`: распаковка CAB, CTL = PKCS#7 contentType `1.3.6.1.4.1.311.10.1` (спека Microsoft MS-CRTD), проверка подписи MS CTL-signer (**signer зашит в бинарник** — иначе циркулярное доверие), отбор корней; рядом `disallowedcertstl.cab` (отозванные). Кэш: бандл-файл, refresh по `nextUpdate` (7–30 дней); между обновлениями — ноль сетевых запросов, офлайн работает на кэше.
- Безопасность: докачанное не создаёт доверие само (обязано выстроиться к якорю); CTL — проверка подписи + пин известной-good версии в бинарнике; AIA-трафик светит IP клиента в сторону CA, но не целевой хост.
- Порядок: T1 → T2 → T3; T3 не блокирует ни один пункт роадмапа.
